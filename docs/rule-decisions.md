# v1.0 運用方針と合意事項

Shinji Hattaが設計したゲームの計算規則を、AIのGMが一貫して適用するための方針をまとめる。標準ルールは [ゲームルール](game-rules.md)、背景は [制度の考え方](concept.md) を参照。ここでは計算時の注意点と、プレイごとに合意する取り決めを区別する。

## 計算規則の適用

- 事業者ADRは5%、市場ADRは2%減価し、市場の減価前残高の3%を社会分散負担として記録する。市場の名目減価の40%が実効減価に当たるのであり、会社のCashから40%分を徴収する意味ではない。
- Cash留保負担は `max(法人税控除後Cash, 0) * 0.02`。Cashが0以下の場合に負担額が負にならないようにする。
- 除去衛星の寿命は成功件数ではなく試行回数。自機デブリ化を含め1試行につき1減らす。寿命の最後に成功した場合も報酬を発行し、その後PMD退役する。PMDそのものは追加報酬を生まない。
- 当ターンの除去報酬は同ターンに売れない。処理順で除去後に売却があっても、この制限は維持する。
- 除去候補の繰り上がりは翌ターン。除去途中に新しい候補を自動補充しない。
- 事故は毎ターン1判定、対象は通信衛星を持つ事業者からランダム選択。衛星数比例の抽選には変更しない。
- 標準収益は1機3 Cash。価格変更時に自動で30%へ再連動させず、初期設定で収益も確認する。
- `S`、`T`、準備資産償還、除去1回8 Cash、6ターン制、旧版の得点式はv1.0に持ち込まない。
- プレイヤーの言語に合わせた表示は従来のリポジトリ方針として維持する。

## 開始時に合意する事項

以下はv1.0の固定ルールではなく、セッション運用の提案として明示する。参加者の合意後に適用し、採用内容をゲームの状態記録に残す。

| 未確定事項 | 運用上の扱い・提案 |
| --- | --- |
| 終了条件・勝敗 | ターン数か参加者の終了合意を確認。独自の得点式を作らない |
| 購入直後の除去衛星 | 翌ターンから使用する案を提示。ターン開始時Cap上限と整合させる。同ターン利用にはCapの変更も合意 |
| 同じ対象への除去・市場ADRの奪い合い | 会社順・試行順を合意し、先行処理で無効になった行動は本人へ再入力を求める |
| 資金不足・借入 | 各フェーズで保有資金内の支出を提案。売却は購入より後なので先取りしない。借入条件は未定義 |
| ADR支払いの損金額 | 衛星購入はPでCash換算する案、通貨交換は費用から除く案を提示。その他費用も確認 |
| ADR取得時期・ロット消費 | 当期発行分を識別し、古いロットから使用、減価は比例配分を提案。購入ADRの再売却条件は該当時に確認 |
| 通信衛星ゼロ時の事故 | 対象不在時の処理は開始時に確認。勝手にデブリを増やさない |
| 保険・SSA/STM等 | 支払い先の例だけで価格・効果がない。旧版の価格・効果を流用せず合意してから実装 |
| NPC | NPCとして参加させる指定を自動操作の委任として扱う。標準のバランス型方針を一度説明し、個別行動の承認は求めない。人間の行動は代行しない |

## 環境差とモデル

単独版は1人の利用者と自動操作のNPCを扱い、ローカルに状態・イベントを保存する。Discord版はスレッドの発言者と会社を対応づけ、人間全員の行動を待つ。NPCの行動はGMが選択する。hubの現行コードは発言者名を本文に付与するため、同名・曖昧な帰属を認証済みユーザーIDのようには扱わない。

Discordでは生成したJSON添付やコードコンテナが次のAPI要求へ自動で渡る保証がない。一方、会話本文は履歴として渡されるため、初期デブリのID対応と正確な状態・イベントを本文に記録し、計算環境を自動再構成する。通常プレイではファイル操作を要求しない。履歴そのものが失われた場合まで復元を保証するものではない。この方式はhub側の永続ゲーム状態機能を前提としない。

Discordの画像表はコードで台帳から描画する。数値の生成画像化はしない。画像＋要約、項目名付きテキスト、Markdown表を選べ、画像を使っても復元用の状態は本文に残す。画像だけに情報を閉じ込めない。表示方法・NPC自動操作の改善は経済ルールの変更ではない。

Discord版は `gpt-5.6-luna` とコード実行を初期設定にする。公式モデル資料でResponses APIとCode interpreter対応を確認した（2026-09-10）。料金は入力 $0.20、キャッシュ入力 $0.02、出力 $1.20 / 100万トークン。コード実行等のツール料金は別途考慮する。

出典: [GPT-5.6 Luna](https://developers.openai.com/api/docs/models/gpt-5.6-luna)。利用者による実プレイで動作を確認しており、標準モデルとして採用している。今後の改良でも、会計一致・入力待ち・重複処理防止・再開を確認する。モデル変更時は `scripts/build_prompts.py` のメタデータから変更して再生成する。

コード実行を指定しても、モデルのルール理解そのものを保証するものではない。現時点ではプロンプト型GMであり、固定実装されたゲームエンジンではない。

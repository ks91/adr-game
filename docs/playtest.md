# v1.0 プレイ検証

discord-agent-hub版は、利用者による `gpt-5.6-luna` での実プレイで動作を確認している。この文書は、今後の改良時にも会計・対話・表示の挙動を確認できるよう、期待値とチェック項目をまとめたもの。固定乱数は検証用に明示し、本番プレイの乱数を望ましい結果に差し替えない。

配布形式についても、共通ソースとの同期、ローカルloglmからのCodex向けインストール、インストール先への本文完全保持・バージョン認識、discord-agent-hubの実パーサーによるモデル・ツール設定の取り込みを確認している。

## 形式と同期

`python3 scripts/build_prompts.py --check` で配布物がソースと一致することを確認する。Discord側の `parse_agent_markdown` でメタデータが解釈できること、共有本文が両方に含まれること、ローカルファイル参照なしで規則が読めることを確認する。

## 会計の期待値

標準パラメータを使用する。

| ケース | 入力 | 期待結果 |
| --- | --- | --- |
| 何もしない会社 | Cash=100、コンステ10機、ADR=0、購入なし、事故なし | 収益30、税6、留保負担2.48、期末Cash=121.52 |
| ADRの所在別減価 | 会社ADR=40、市場ADR=10、M=50、他のADR移動なし | 会社38、市場9.8、M=47.8、消滅2.2、社会負担0.3。社会負担をCashから引かない |
| 最後の試行で成功 | 残寿命1、V=8、r=0.79 | ADR16発行、Dが1減少、寿命0でPMD退役。減価後会社ADR15.2。同ターン売却不可 |
| 最後の試行で無事失敗 | 残寿命1、r=0.80 | 報酬なし、対象残存、寿命0でPMD退役。新規デブリなし |
| 最後の試行で自機デブリ化 | 残寿命1、r=0.95 | 報酬なし、対象残存、寿命0、V=3の新規デブリ1個。PMD扱いにしない |
| 売買 | 売却可能ADR10を売り、別会社が4購入 | 売手Cash+10、市場ADRは差引+6、買手Cash-4/ADR+4、M不変（減価前） |
| 購入上限 | 市場ADR3に対して4購入を宣言 | 新規発行・負残高・勝手な3への減額をせず、本人へ修正を求める |
| 事故 | D=100、Sat_total=25、r=0.145 | 事故率0.145、事故発生。対象企業を別に抽選し、衛星1機喪失、新規V=3を1個追加 |
| 負のCash | 税控除後Cash=-5 | 留保負担0。借入や利息を新設しない |

全ケースで `M=会社ADR合計+市場ADR`、`期首M+累積発行-累積消滅=M` を照合する。

## 対話・再開

1. 日本語で開始し、初期条件と運用上の未確定事項の合意を待つ。英語の別セッションでも同じ手順を確認する。
2. 1人＋NPCで、人間の担当と標準NPC方針を確認する。NPCを指定したら以後は自動行動し、毎ターンの指示や承認を要求しない。人間を勝手にNPCへ変更しない。
3. Discordで人間2人が参加し、片方だけ入力した状態では処理へ進まない。観戦者による他社の行動指定も採用しない。
4. 2社が同じデブリを指定し、先行除去成功後の後続行動を無断で代替しない。修正時に先行処理・収益を再適用しない。
5. 乱数を伴う途中フェーズで中断・再開し、保存記録から未処理の部分だけを進める。Discordは計算環境が空でも会話本文から復元し、JSONのアップロードを求めない。
6. 同じメッセージの再送、状態への質問、次ターン確認の待機によって、税や収益が二重適用されない。
7. 子供向け表示と通常表示で、同じ入力と乱数なら数値が一致する。
8. 合意した終了条件まで完走し、期末保存データから全会社・全デブリ・全除去衛星・累積フローを復元できる。
9. Discordで複数ターン進め、JSONの作成・ダウンロード・再送を一度も人間へ要求しない。初期のID別V、ADRロット、途中処理のカーソルが会話本文から復元できることも確認する。
10. 画像表の日本語フォント・スマホでの可読性を確認する。表セル・見出し・会社名を含め全描画文字のグリフを確認する。日本語フォントなし、指定フォントが存在しない、会社名に未対応文字がある場合は、トウフ画像を投稿せず日本語の項目名付きテキストで継続する。画像と本文が同じ台帳値を表示することも確認する。
11. テキスト表示を1人が要求したら、他の人が画像を好んでも必要な全項目を読み上げやすい形で提示する。Markdown表の明示指定も保持する。
12. NPCの対象が先行行動で消えたら、合意済み規則内でNPCが自動再選択する。人間の対象変更は本人へ確認する。NPCは乱数結果を見てから当初の行動を選び直さない。
13. Discordの日本語表示では、画像・本文・Markdown表・子供向け説明を通して constellation satellites が「通信衛星」、demurrage が「減価」、debris が「デブリ」になる。Cash留保負担や内部のSat_totalは別の意味に変更しない。
14. 表示方法を指定せず新規ゲームを開始し、最初の資産表・デブリ候補からPNGが添付される。「画像にして」という追加入力が不要で、本文の状態記録もMarkdown表にならない。画像化失敗時は項目名付きテキストで継続する。
15. PNG内の見出し・値が独立したセルに配置され、Markdownのパイプや区切り行を描いた画像ではないことを確認する。明示的にMarkdown表示を選んだ後はその選択を保持し、画像へ戻す指示も反映する。

改良時は同じシナリオを複数回実施し、会計不一致・入力待ち違反・状態喪失と実際のAPI/ツール費用を記録して比較する。`/session-show`、`/usage-report`、`/log-export` を利用できる。
